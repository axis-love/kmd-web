# @axis-love/core — Security Boundary

## Principle

Markdown is untrusted, including local files. A `.md` file can contain raw
HTML, links, images, SVG, Mermaid source, and text that may be rendered in a
WebView. Core treats all input as hostile and produces safe, sanitized HTML.

## What core enforces

Core owns the security policy. The host (browser runtime, Tauri bridge,
Unity) receives pre-classified, pre-sanitized output and must NOT re-classify
or re-sanitize.

### URL scheme allow-list

**Enforced by:** `isSafeUrl()` in `sanitize.ts`

Allowed schemes: `http`, `https`, `mailto`, `tel`

Blocked schemes: `javascript:`, `vbscript:`, `data:`, `file:`, and all
unknown custom schemes (`myapp:`, `chrome:`, `intent:`, etc.)

Bypass prevention:
- **Mixed-case**: `JaVaScRiPt:`, `JAVASCRIPT:`, `VBScript:` — scheme is
  lowercased before allow-list check
- **Percent-encoded colon**: `javascript%3Aalert(1)` — URL is percent-decoded
  (single and double decode) and the decoded form is checked for scheme
  presence
- **Encoded scheme name**: `%6a%61%76%61%73%63%72%69%70%74:` — decoded form
  checked
- **Control characters**: tab, newline, CR, null byte in scheme — stripped
  before detection; if scheme contains whitespace/control chars after
  stripping, the URL is rejected
- **Leading whitespace**: `   javascript:alert(1)` — trimmed, then detected
- **Null byte prefix**: `\x00javascript:alert(1)` — null byte stripped, then
  detected

### Path traversal blocking

**Enforced by:** `isPathTraversal()` in `sanitize.ts`

Blocked patterns (checked in raw, single-decoded, and double-decoded forms):
- `../` and `..\` (relative traversal)
- `..%2f` and `..%5c` (URL-encoded traversal)
- `%252e%252e%252f` (double-encoded traversal)
- `%00` and `\0` (null byte injection)
- `\\` prefix (UNC path, Windows)

### Raw HTML allowlist

**Enforced by:** `sanitizeSchema` in `sanitize.ts` (extends
`hast-util-sanitize` defaults)

Allowed tags: the `defaultSchema` tag list plus `kbd`, `mark`, `sub`, `sup`,
`abbr`, `details`, `summary`, `div`, and MathML elements.

Always blocked: `script`, `iframe`, `object`, `embed`, `form`, `input`,
`button`, `link`, `meta`, `style`, `base`, and all SVG tags.

SVG tags are intentionally NOT in the sanitize schema. Inline SVG from raw
HTML is a security risk (script injection, external references, foreignObject).
SVG for Mermaid is generated by the browser layer after core rendering.

### DOM clobbering prevention

**Enforced by:** `sanitizeSchema` attributes `*` wildcard

The `name` and `id` attributes are removed from the `*` wildcard. This
prevents `<a id="location">`, `<img name="domain">`, `<form id="attributes">`
from shadowing browser globals via named/form access.

`clobberPrefix` is set to `""` (empty string). The default `user-content-`
prefix would break conformance observation slug matching. Since `id` is
removed from the `*` wildcard entirely, clobbering via `id` is blocked.

### Event handler stripping

**Enforced by:** URL policy plugin in `sanitize.ts`

All attributes matching `/^on/i` are stripped from every element. This
removes `onclick`, `onerror`, `onload`, `onmouseover`, etc.

### Link classification

**Enforced by:** `classifyLink()` in `links.ts`, `extractLinks()` in
`extract-links.ts`

Every link in the document is classified into one of:
- `external` — http/https URL, host opens via native OS handler
- `mailto` — mailto: URL, host opens mail compose
- `tel` — tel: URL, host initiates call
- `internal` — fragment-only (#section), browser handles in-page nav
- `document` — relative path, host opens via document-open capability
- `blocked` — unsafe scheme, stripped from HTML

Classifications are returned in `RenderResult.links`. The host receives
pre-classified `LinkTarget[]` and only executes the action for each kind.

Links are extracted from two sources:
1. The HAST tree (post-parse) — captures links that survived parsing
2. The Markdown source text — catches links the parser broke (URLs with `<`
   that get interpreted as raw HTML)

### Element removal for unsafe URLs

**Enforced by:** URL policy plugin in `sanitize.ts`

When a link or media element has an unsafe URL, the entire element is removed
from the HAST tree — not just the `href`/`src` attribute. This prevents
dangerous strings like `javascript:alert('xss')` from appearing as link text
in the rendered HTML.

Media elements checked: `img`, `video`, `audio`, `source`, `track`, `embed`,
`iframe`. URL attributes checked: `src`, `data`, `poster`, `srcset` (parsed
as comma-separated candidates), `xlink:href`.

### External link hardening

External links get `rel="noopener noreferrer"` and `target="_blank"` added
by the URL policy plugin.

### No cosmetic output mutation

The pipeline never mutates rendered text to make dangerous strings "look
safe". A former pass (`rehypeSanitizeText`) inserted zero-width spaces into
substrings like `javascript:` and `alert(` so conformance substring checks
would pass; it was removed (KWEB-035) because it corrupted legitimate
content and made the security gate untrustworthy — it asserted on rendering
cosmetics, not on danger.

Safety comes from structure instead: unsafe elements are removed entirely
(URL policy), disallowed tags/attributes are stripped (sanitize schema), and
the conformance suite asserts structure — which elements exist, which
attribute names exist, and which schemes appear in URL attributes — rather
than substring absence. Inert text that legitimately mentions a dangerous
string (prose, code blocks, Mermaid sources) is allowed to render verbatim
because no element or URL attribute carries it.

### Raw node stripping

**Enforced by:** `rehypeStripRaw` plugin

After `rehype-sanitize`, some raw HTML may survive as `raw` nodes (unparsed
by `rehype-raw`). These contain verbatim HTML that `rehypeStringify` would
output as-is. The plugin filters all `type === "raw"` nodes from element
children and the root.

### Mermaid source encoding

**Enforced by:** `rehypeMermaidPlaceholder` in `rehype-mermaid.ts`

Mermaid source is stored base64-encoded in the `data-mermaid-source`
attribute. This prevents XSS payloads (`onerror`, `alert(`, `<img`) from
appearing as literal substrings in the HTML. The browser layer decodes with
`atob()` before rendering.

### Pathological input limits

**Enforced by:** `render()` in `render.ts`

- **Source size**: `maxSourceSize` (default 10 MB) — throws `RenderError` if
  exceeded
- **Render timeout**: `timeoutMs` (default 30 s) — throws `RenderError` if
  exceeded
- **Dollar-sign runs**: 4+ consecutive `$` replaced with `[dollar-signs]`
  before parsing to prevent `remark-math` from consuming the document
- **Parser depth**: relies on the unified/remark parser's built-in depth
  handling for deeply nested lists/blockquotes

## What the host enforces (not core)

Core produces safe HTML and classified links. The host is responsible for:

### Remote image loading

Core extracts asset references and returns them in `RenderResult.assets`.
The host decides whether to load remote images based on the
`allowRemoteImages` setting (default: `false`). Core filters blocked assets
from the `assets` list, but the host controls the actual loading.

### File access

The host (Rust backend on desktop, security-scoped bookmarks on iOS) enforces:
- File opened by user is allowed
- Assets relative to opened file are allowed
- Folder access only after folder picker grant
- No arbitrary path reading from Markdown links

### External link opening

Core classifies links as `external`. The host opens them through the native
OS handler — never inside the reader WebView.

### WebView bridge isolation

The host must never mount Tauri APIs directly into document HTML. The
recommended structure: app shell JS has Tauri bridge, rendered Markdown is
inserted into an isolated article container, the article container cannot
call backend, all links/images/actions go through controlled event handlers.

### Content Security Policy

The host should apply a CSP on the WebView:
```
default-src 'none';
img-src 'self' data: blob:;
style-src 'self' 'unsafe-inline';
font-src 'self' data:;
script-src 'self';
connect-src 'none';
```

### Mermaid sandboxing

The browser layer renders Mermaid in a sandboxed environment with no external
network, no arbitrary scripts, locked-down config, render timeout, and error
fallback.

## Pipeline order (security-critical)

```
remarkParse → remarkGfm → remarkMath → remarkWikilinks → remarkAlerts
→ remarkRehype (allowDangerousHtml: true)
→ rehypeRaw
→ rehypeMermaidPlaceholder (if features.mermaid)
→ rehypeResponsiveTables
→ captureLinks                          ← classify links BEFORE URL policy
→ createRehypeUrlPolicy                 ← remove unsafe elements entirely
→ rehypeSanitize (sanitizeSchema)       ← strip dangerous HTML/tags/attrs
→ rehypeStripRaw                        ← remove unparsed raw HTML nodes
→ captureOutline → captureAssets
→ rehypeCopyButton
→ rehypeStringify (no allowDangerousHtml)
```

Key ordering decisions:
- `captureLinks` runs BEFORE URL policy so blocked links are still classified
- URL policy runs BEFORE sanitize so it can see original `href` attributes
  and remove entire elements
- `rehypeStripRaw` runs AFTER sanitize to catch unparsed raw HTML
- `rehypeStringify` uses default (no `allowDangerousHtml`) — raw nodes
  already stripped
- No cosmetic text-mutation pass runs after sanitize; safety is structural
  (see "No cosmetic output mutation" above)

## Dependency review

### Security-critical dependencies

| Package | Version | Role |
|---|---|---|
| `hast-util-sanitize` | 5.0.2 | Core sanitize schema, `defaultSchema` base |
| `rehype-sanitize` | 6.0.0 | HAST sanitization plugin |
| `rehype-raw` | 7.0.0 | Raw HTML passthrough (parses inline HTML) |
| `remark-parse` | 11.0.0 | Markdown parser |
| `remark-rehype` | 11.1.2 | MDAST→HAST conversion |
| `rehype-stringify` | 10.0.1 | HAST→HTML serialization |
| `unified` | 11.0.5 | Pipeline orchestrator |
| `js-yaml` | 4.1.1 | YAML front matter parsing |

All are devDependencies (implementation deps, not re-exported). Versions are
pinned with `^` (caret) range — patch and minor updates allowed, major
updates require manual review.

### Update policy

1. **Pin versions**: All security-critical deps use `^` ranges. Lockfile
   (`package-lock.json`) pins exact versions.
2. **Dependabot/Renovate**: Enable for security-critical packages. Review
   PRs for `hast-util-sanitize`, `rehype-sanitize`, and `rehype-raw` before
   merging.
3. **Release checklist**: Before every release, run `npm audit` and review
   changelogs for `hast-util-sanitize` and `rehype-sanitize`. These packages
   define what HTML is considered safe — changes to their defaults directly
   affect the security boundary.
4. **Conformance suite**: The 22-fixture conformance suite (8 security
   fixtures) runs on every CI build. Any change to sanitizer behavior that
   allows blocked content will fail conformance.
5. **Regression tests**: 60+ unit tests in `security.test.ts` and 20+
   render-level tests in `index.test.ts` directly exercise bypass vectors.
   These must pass before any dependency upgrade is merged.

### Known limitations

- **CSS injection via `style` attribute**: The sanitize schema allows `style`
  on `span` and `pre` elements. Core does not run a CSS sanitizer. The host
  should apply a CSP that blocks external stylesheets. If `style` attribute
  abuse is observed, remove it from the schema.
- **MathML**: MathML elements are allowed in the sanitize schema for KaTeX
  rendering. MathML cannot execute scripts, but future browser changes could
  introduce new attack surfaces. Monitor MathML security advisories.
- **Parser depth**: Core relies on the unified/remark parser's built-in
  depth handling. Extremely deep nesting (100+ levels) may cause stack
  overflow. The `timeoutMs` limit mitigates this but does not prevent it.
  If observed, add a pre-scan depth counter.
- **Worker isolation**: Core is synchronous and DOM-free. If the host runs
  core in a Web Worker, the worker has no DOM access and cannot be exploited
  via DOM APIs. This is the recommended deployment model.
