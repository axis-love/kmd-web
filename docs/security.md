# Security

kmd-web treats all Markdown as **untrusted** — including local files. The rendering pipeline is designed so that untrusted input cannot execute scripts, access privileged host APIs, or exfiltrate data. Security policy is owned by `@axis-love/core` and cannot be bypassed by host capabilities.

## Trust model

- **All Markdown is untrusted**, including documents loaded from the local filesystem.
- Core classifies and validates every URL, tag, and attribute. Host capabilities (link handlers, asset resolvers) only carry out already-classified, already-validated actions.
- The host must explicitly relax security defaults via `SecurityOptions` — the defaults are always restrictive.

## Sanitization pipeline

Sanitization happens **after parsing and transforms**, not before. The pipeline in `@axis-love/core/src/render.ts`:

1. `remarkParse` — parse Markdown to mdast
2. `remarkGfm` — GFM extensions (tables, task lists, autolinks)
3. `remarkMath` — math syntax
4. `remarkWikilinks` — `[[wikilink]]` syntax
5. `remarkAlerts` — GitHub-style alert blocks
6. `remarkRehype` (with `allowDangerousHtml: true`) — convert to hast, preserving raw HTML nodes
7. `rehype-raw` — parse raw HTML nodes into proper hast elements
8. `rehypeMermaidPlaceholder` — replace Mermaid code blocks with structural placeholders
9. `rehypeResponsiveTables` — wrap tables in scroll containers
10. `createRehypeUrlPolicy` — remove elements with unsafe URLs, strip event handlers, add `rel="noopener noreferrer"`
11. `rehypeSanitize` (with custom `sanitizeSchema`) — sanitize the hast tree
12. `rehypeStripRaw` — remove any surviving `raw` nodes (unparsed HTML)
13. `rehypeSanitizeText` — sanitize text content
14. `rehypeStringify` — serialize to HTML

This order ensures that all transformations (math, Mermaid placeholders, tables) are sanitized. Raw HTML that survives parsing but is not in the allowlist is stripped.

## Raw HTML allowlist

Only a strict set of inline HTML tags is permitted in raw HTML blocks. Tags not in this list are **stripped** (the tag is removed; text content may be preserved).

Default allowed tags (from `SecurityOptions.allowedRawHtmlTags`):

```
br, kbd, sub, sup, mark, abbr, details, summary
```

The sanitize schema (in `@axis-love/core/src/sanitize.ts`) extends `rehype-sanitize` defaults with these tags plus structural tags needed by features:

- `div` — GitHub alert wrappers, Mermaid placeholders
- KaTeX MathML elements: `math`, `semantics`, `mrow`, `mi`, `mo`, `mn`, `msup`, `msubsup`, `annotation`, `mop`, `mtext`, `mfrac`, `msqrt`, `mroot`, `mfenced`, `mtable`, `mtr`, `mtd`, `munderover`, `munder`, `mover`, `mpadded`, `mspace`, `menclose`, `mglyph`, `mlabeledtr`, `mmultiscripts`, `msub`

**SVG tags are intentionally NOT allowed** in the core sanitize schema. Inline SVG from raw HTML is a security risk (script injection, external references). SVG for Mermaid diagrams is generated by the browser layer after core rendering, not through the unified pipeline.

## URL scheme policy

### Blocked URL schemes

The following schemes are **always blocked** regardless of configuration:

- `javascript:` — script execution
- `vbscript:` — script execution (legacy IE)
- `data:` — unsafe data URLs (e.g. `data:text/html,<script>...`)
- `file:` — arbitrary file access
- Unknown custom schemes — anything not in the allowed list

### Allowed link schemes (default)

```typescript
// SecurityOptions.allowedLinkSchemes defaults:
["https", "http", "mailto", "tel"]
```

Relative links and fragment-only references (`#section`) are always allowed regardless of the scheme allowlist. The scheme list only governs absolute URLs with a scheme component.

To allow additional schemes:

```typescript
const result = await render(source, {
  security: {
    allowedLinkSchemes: ["https", "http", "mailto", "tel", "ftp"],
  },
});
```

### URL validation (`isSafeUrl`)

The `isSafeUrl()` function in `@axis-love/core/src/sanitize.ts` performs multiple checks:

1. **Control character stripping**: Tab, newline, carriage return, null, and all control characters (`\x00-\x1F`, `\x7F`) are stripped before scheme detection. Browsers ignore these when parsing URLs — an attacker can insert them to break scheme detection (e.g. `"java\tscript:"` is treated as `"javascript:"` by browsers).

2. **Path traversal detection**: Checks for `../`, `..\\`, `..%2f`, `..%5c`, null bytes (`%00`, `\0`), and UNC paths (`\\`). Checks both the raw URL and percent-decoded forms (single and double decode).

3. **Percent-encoded colon bypass prevention**: A URL like `"javascript%3Aalert(1)"` has no raw `:` but decodes to `"javascript:alert(1)"`. The function checks both the raw form and percent-decoded form (up to double decoding) for encoded colons (`%3A`, `%253A`). If the decoded form has a scheme not in the allowlist, the URL is blocked.

4. **Scheme validation**: The scheme portion must not contain whitespace or control characters (browsers strip these). If it does, the URL is treated as unsafe.

5. **Fail-closed**: If the URL doesn't match any safe pattern, it is rejected.

### Remote images

Remote images are **blocked by default** (`SecurityOptions.allowRemoteImages = false`). When blocked, the image element is stripped from the rendered HTML and a diagnostic is emitted.

To allow remote images:

```typescript
const result = await render(source, {
  security: { allowRemoteImages: true },
});
```

Even when allowed, remote image URLs must pass `isSafeUrl()` scheme validation. Local/relative image URLs are always allowed (they are resolved through the host's `AssetResolver`).

## External links

External links (`https://`, `http://`) **leave the reader through a validated host action**. The pipeline:

1. Core classifies the link as `external` via `classifyLink()`.
2. The URL policy adds `rel="noopener noreferrer"` and `target="_blank"` to the `<a>` element.
3. The browser runtime's `LinkPolicy` intercepts clicks and routes them to `LinkHandler.openExternal(url)`.
4. If no `LinkHandler` is provided, the default behavior opens the URL with `window.open(url, "_blank", "noopener,noreferrer")`.

`mailto:` and `tel:` links are also routed through `LinkHandler.openExternal`.

## Feature isolation

Mermaid, math, and SVG **cannot fetch arbitrary external resources**:

- **Mermaid**: Configured with `securityLevel: "strict"` and `startOnLoad: false`. The Mermaid source is base64-encoded in the HTML to prevent XSS payloads from appearing as literal substrings. Rendering happens in the browser layer with a 10-second timeout and a readable source fallback.
- **Math (KaTeX)**: Configured with `trust: false` (blocks `\input`, `\includegraphics`, `\url`, `\href` with unsafe protocols, `\htmlClass`, `\htmlId`, `\htmlStyle`, `\htmlData`), `maxExpand: 1000` (prevents macro expansion DoS), and `macros: {}` (no custom macros).
- **SVG**: Inline SVG from raw HTML is not allowed in the sanitize schema. SVG for Mermaid diagrams is generated by the browser layer, not from user-supplied raw HTML.

## Timeout and limits

Heavy rendering has timeouts, size limits, and readable fallbacks:

| Limit | Default | Configurable via |
|---|---|---|
| Maximum source size | 10,485,760 bytes (10 MB) | `RenderOptions.maxSourceSize` |
| Overall render timeout | 30,000 ms (30 s) | `RenderOptions.timeoutMs` |
| Mermaid per-diagram timeout | 10,000 ms (10 s) | `FeatureCoordinationOptions.mermaidTimeoutMs` |
| Mermaid max source length | 50,000 characters | Hardcoded (`MAX_DIAGRAM_SOURCE_LENGTH`) |
| KaTeX max macro expansion | 1,000 | Hardcoded (`SAFE_MAX_EXPAND`) |

When a timeout is exceeded, a `RenderError` with code `"render-timeout"` is thrown (for the overall render) or a readable fallback is produced (for Mermaid).

## Host API isolation

**Rendered content cannot invoke Tauri or privileged host APIs.** The rendered HTML is plain HTML — it contains no script tags, no event handlers, and no references to host APIs. Host capabilities (`LinkHandler`, `AssetResolver`, `ClipboardProvider`, `WorkerFactory`) are JavaScript objects consumed by the browser runtime; they are not exposed to the rendered content.

The `<kmd-reader>` custom element dispatches `kmd:link-external` and `kmd:link-document` events from its own `dispatchEvent` method — rendered Markdown content has no access to `dispatchEvent` on the host element. Only the element's internal code creates events, and only after core has validated the URL.

## RenderResult guarantees

### `RenderResult.links` — all links classified

`RenderResult.links` classifies **ALL links**, including blocked ones. Classification happens **before** the URL policy removes unsafe elements from the HTML. This means:

- Every link in the source Markdown appears in `links` with its `kind` (`external`, `mailto`, `tel`, `internal`, `document`, or `blocked`).
- Blocked links have `kind: "blocked"` and a `reason` explaining why (e.g. `"unsafe-url"`).
- The host can inspect `links` to understand what was in the document, even for links that were stripped from the rendered HTML.

```typescript
export interface LinkTarget {
  readonly kind: LinkTargetKind;
  readonly rawUrl: string;       // Original URL from source
  readonly resolvedUrl?: string; // Normalized URL (undefined for blocked)
  readonly reason?: string;      // Only for blocked targets
}
```

### `RenderResult.html` — must not contain unsafe URLs

The rendered HTML must not contain `javascript:`, `vbscript:`, or unsafe `data:` URLs. The URL policy removes elements with unsafe URLs entirely (including text content) to prevent dangerous strings from appearing in the output.

## DOM clobbering prevention

The sanitize schema prevents DOM clobbering attacks:

- The `name` and `id` attributes are **stripped** from the sanitize wildcard (`"*"` attribute list). The schema explicitly filters them out:

```typescript
"*": [
  ...(defaultAttributes["*"] ?? []).filter(
    (attr) => attr !== "name" && attr !== "id"
  ),
  "className",
],
```

- `rehype-sanitize` is configured with `clobberPrefix: ""` (no prefix). Since `name` and `id` are already stripped from the wildcard, there is nothing to clobber — the empty prefix avoids the default `user-content-` prefix on legitimate attributes.

## rehype-sanitize configuration

The custom sanitize schema (`sanitizeSchema` in `@axis-love/core/src/sanitize.ts`) extends `rehype-sanitize` defaults:

- **`clobberPrefix: ""`** — no prefix needed because `name`/`id` are already stripped.
- **`tagNames`**: defaults + safe inline HTML tags + `div` (alerts/Mermaid) + KaTeX MathML elements. No SVG tags.
- **`attributes`**: extended per-element allowlists for `a` (`rel`, `target`), `div` (`className`, `dataMermaidSource`), `p` (`className`), `span` (`className`, `style`), `pre` (`className`, `dataLanguage`, `tabindex`, `style`), `code` (`className`), `math` (`xmlns`, `display`), `annotation` (`encoding`).
- **`"*"` wildcard**: `className` is allowed on all elements, but `name` and `id` are removed.

## Content Security Policy (CSP)

kmd-web generates safe HTML. No `unsafe-inline` is needed in the CSP:

- **HTML**: The library generates safe HTML through the unified pipeline. All inline HTML passes through the sanitize schema. No inline event handlers (`onclick`, etc.) are produced.
- **CSS**: Reader styles come from `@axis-love/styles` (a stylesheet file), not inline styles. The only inline `style` attributes are on Shiki highlighting spans (for syntax colors) and are generated by Shiki's safe output.

### Recommended CSP

```
default-src 'self';
script-src 'self';
style-src 'self';
img-src 'self' data: blob:;
font-src 'self';
worker-src 'self' blob:;
connect-src 'self';
```

### Notes

- **`script-src`**: Does not need `'unsafe-inline'` or `'unsafe-eval'`. The library never generates inline scripts. Shiki uses its JavaScript regex engine, not `eval`.
- **`style-src`**: Does not need `'unsafe-inline'`. Styles come from the `@axis-love/styles` stylesheet. Shiki inline `style` attributes contain only `color` and `background-color` declarations — if your CSP requires blocking inline styles, you will need to handle Shiki's output (e.g. via a nonce or by post-processing). For most deployments, `'self'` is sufficient.
- **`worker-src`**: Required if you use `WorkerFactory` to offload rendering to a Web Worker. Workers are created from same-origin or `blob:` URLs. Use `'self' blob:`.
- **`img-src`**: Include `data:` and `blob:` if you resolve local assets to blob/data URLs via `AssetResolver`.
- **`connect-src`**: If you allow remote images (`allowRemoteImages: true`), ensure `connect-src` (or `img-src`) permits the remote origins.

## Safe defaults

All security defaults are **restrictive**. The host must explicitly relax them via `SecurityOptions`:

| Option | Default | Effect |
|---|---|---|
| `allowRemoteImages` | `false` | Remote images stripped, diagnostic emitted |
| `allowedLinkSchemes` | `["https", "http", "mailto", "tel"]` | All other schemes blocked |
| `allowedRawHtmlTags` | `["br", "kbd", "sub", "sup", "mark", "abbr", "details", "summary"]` | All other raw HTML tags stripped |
| `maxSourceSize` | 10,485,760 (10 MB) | Sources exceeding this are rejected |
| `timeoutMs` | 30,000 (30 s) | Renders exceeding this timeout fail |

```typescript
export const defaultRenderOptions = {
  features: {
    codeHighlighting: true,
    mermaid: true,
    math: true,
    designDoc: true,
  },
  security: {
    allowRemoteImages: false,
    allowedLinkSchemes: ["https", "http", "mailto", "tel"],
    allowedRawHtmlTags: ["br", "kbd", "sub", "sup", "mark", "abbr", "details", "summary"],
  },
  maxSourceSize: 10_485_760,
  timeoutMs: 30_000,
  baseUrl: undefined,
};
```

## Security responsibilities

| Layer | Responsibility |
|---|---|
| Core (`@axis-love/core`) | URL classification, sanitization, raw HTML allowlist, feature detection, link classification |
| Browser (`@axis-love/browser`) | DOM enhancement, click interception (delegates to core classification), asset URL lifecycle |
| Host capabilities | Execute already-classified actions (open links, resolve assets, write clipboard). Never re-validate or re-classify. |
| Host application | CSP headers, asset loading policy, platform-specific link handling |

**Capabilities never re-validate URLs or decide safety.** Core classifies actions; capabilities only carry out already-classified actions. This prevents host adapters from bypassing core security policy.
